# 43. Ассемблер и компоновщик КР580ВМ80А

*Это не статья журнала, а руководство к инструментам эмулятора.* В репозитории есть
кросс-ассемблер и компоновщик для процессора КР580ВМ80А, рассчитанные на «ЮТ-88»:
программу пишут на ПК на языке ассемблера в мнемонике Intel, собирают в файл, который
загружает эмулятор, и запускают.

- **`asm-k580vm80a`** — ассемблер: один исходный файл → двоичный образ, дамп в формате
  журнала, Intel HEX или перемещаемый объектный файл `.link`. Есть препроцессор
  (`INCLUDE`, `IF`, `MACRO`, `REPT`) и листинг.
- **`link-k580vm80a`** — компоновщик: несколько модулей `.link` → один образ bin/hex/Intel
  HEX и карта компоновки.

Полный справочник встроен в программы: `asm-k580vm80a -h` и `link-k580vm80a -h`
(по-английски — `-he`). Здесь — обзор с примерами; при расхождении верна встроенная
справка. Английская версия этого руководства — [docs/ASSEMBLER.md](../docs/ASSEMBLER.md).

## 1. Сборка

Обе программы входят в рабочее пространство Cargo (крейт `crates/asm-k580vm80a`) и
собираются вместе с эмулятором:

```sh
make            # cargo build --release
target/release/asm-k580vm80a -h
target/release/link-k580vm80a -h
```

Все команды `make` ниже сначала собирают их.

## 2. Быстрый старт

`examples/asm/hello.asm` выводит две строки на экран дисплейного модуля подпрограммой
МОНИТОРА-F F809H и возвращается к приглашению МОНИТОРА-F:

```asm
PUTCH   EQU     0F809H          ; МОНИТОР-F: вывод символа из C
WARM    EQU     0F86CH          ; МОНИТОР-F: тёплый старт (приглашение «=>»)

        ORG     3000H
START:  LXI     H,MSG
NEXT:   MOV     A,M
        ORA     A               ; 0 — конец строки
        JZ      DONE
        MOV     C,A
        PUSH    H
        CALL    PUTCH
        POP     H
        INX     H
        JMP     NEXT
DONE:   JMP     WARM

MSG:    DB      0DH,0AH,'HELLO, WORLD!'
        DB      0DH,0AH,'ПРИВЕТ, ЮТ-88!',0
        END     START
```

Собрать и запустить в эмуляторе:

```sh
make asm-run F=examples/asm/hello.asm
```

Появится `examples/asm/hello.hex`, будет выбрана полная конфигурация (программа
вызывает F809H), и эмулятор запустится с `--load examples/asm/hello.hex --run 3000`.
То же вручную:

```sh
target/release/asm-k580vm80a -f examples/asm/hello.asm -o hello.hex
target/release/ut88 --config full --load hello.hex --run 3000
```

## 3. Ключи ассемблера

```
asm-k580vm80a -f ВХОД.asm -o ВЫХОД [-t bin|hex|ihex|link] [-l ЛИСТИНГ.lst]
              [-D ИМЯ[=ЗНАЧЕНИЕ]]... [-I ПАПКА]... [--fill XX] [--charset koi7|ascii]
              [--base АДРЕС]
```

| Ключ                | Назначение                                                                                   |
|---------------------|----------------------------------------------------------------------------------------------|
| `-f ФАЙЛ`           | исходный текст (обязателен), UTF-8                                                           |
| `-o ФАЙЛ`           | выходной файл (обязателен); при ошибках не создаётся                                         |
| `-t ТИП`            | тип выхода `bin`, `hex`, `ihex`, `link`; важнее расширения `-o`                              |
| `-l ФАЙЛ`           | записать листинг                                                                             |
| `-D ИМЯ[=ЗНАЧЕНИЕ]` | определить символ, как `EQU` в начале текста (без значения — 1); можно повторять             |
| `-I ПАПКА`          | папка поиска для `INCLUDE` и `INCBIN`; можно повторять                                       |
| `--fill XX`         | байт-заполнитель пропусков в bin (шестнадцатеричный, по умолчанию 00)                        |
| `--charset К`       | кодировка строк: `koi7` (по умолчанию, знакогенератор ЮТ-88) или `ascii`                     |
| `--base АДРЕС`      | адрес `CSEG` при сборке сразу в bin/hex/ihex (по умолчанию 0000); с `-t link` не применяется |
| `-h`, `-he`, `-V`   | справка по-русски, по-английски, версия                                                      |

Без `-t` тип берётся по расширению: `.bin`/`.rom` — bin, `.hex` — дамп журнала,
`.ihx`/`.ihex` — Intel HEX, `.link` — объектный файл; другое расширение без `-t` —
ошибка. Код выхода: 0 — успех, 1 — ошибки сборки, 2 — ошибка в командной строке.

```sh
asm-k580vm80a -f prog.asm -o prog.hex                 # дамп для эмулятора
asm-k580vm80a -f prog.asm -o prog.bin -l prog.lst     # образ и листинг
asm-k580vm80a -f prog.asm -o prog.ihx -D DEBUG        # Intel HEX, символ DEBUG = 1
asm-k580vm80a -f prog.asm -o prog.txt -t hex          # тип задан явно
```

## 4. Синтаксис

```
[метка[:]]  [мнемоника|директива  [операнды]]  [; комментарий]
```

- **Метка** — имя с двоеточием в любом месте строки или имя без двоеточия с первого
  столбца. Имя перед `EQU`, `SET` и `MACRO` — всегда метка.
- **Имена**: латинские буквы, цифры, `_ ? @ .`, первая — не цифра. Регистр букв нигде не
  важен: `Loop`, `LOOP` и `loop` — одно имя. Имена регистров (`A B C D E H L M SP PSW`)
  и слова-операторы (`MOD SHL SHR AND OR XOR NOT EQ NE LT LE GT GE HIGH LOW`)
  зарезервированы — поэтому метку «M» из журнальной программы заполнения памяти пришлось
  переименовать (`examples/asm/fill.asm`).
- **Числа**: `0C000H` (шестнадцатеричное с суффиксом, впереди цифра), `$C000`, `0xC000`,
  `1010B`, `17O`/`17Q`, `99`/`99D`; символьные константы `'A'`, `'AB'` (слово, первый
  символ — старший байт). `$` — адрес текущей строки.
- **Выражения** (по убыванию приоритета): `( )`; унарные `+ - HIGH LOW`;
  `* / MOD SHL SHR`; `+ -`; сравнения `EQ NE LT LE GT GE` (и `= <> < <= > >=`, истина —
  0FFFFH); `NOT`; `AND`; `OR XOR`. Байт-операнд допускает −256…255, слово — −65535…65535.
- **Перемещаемые значения**: адреса меток в `CSEG`/`DSEG` и символы `EXTRN` известны
  только после размещения. Можно: `метка ± константа`, `метка1 − метка2` одного
  сегмента, `HIGH метка`, `LOW метка`, сравнение меток одного сегмента. Остальное —
  ошибка «выражение нельзя переместить».
- **Команды**: все 244 документированных кода КР580ВМ80А в мнемонике Intel (`MOV`,
  `MVI`, `LXI`, …, `RST 0…7`); недокументированные коды не собираются. Таблица команд —
  [10-sistema-komand.md](10-sistema-komand.md).

## 5. Директивы

| Директива                 | Назначение                                                                |
|---------------------------|---------------------------------------------------------------------------|
| `ORG адрес`               | адрес следующих байтов (в `CSEG`/`DSEG` — смещение в сегменте)            |
| `имя EQU выражение`       | постоянный символ                                                         |
| `имя SET выражение`       | переопределяемый символ                                                   |
| `DB` / `DEFB`             | байты и строки: `DB 'ТЕКСТ',0DH,0AH,0`; кавычка внутри строки удваивается |
| `DW` / `DEFW`             | слова, младший байт первым                                                |
| `DS n[,заполнитель]`      | резерв n байт или n одинаковых байтов                                     |
| `END [адрес]`             | конец текста; адрес — точка пуска                                         |
| `INCBIN "файл"`           | вставить двоичный файл                                                    |
| `CSEG` / `DSEG` / `ASEG`  | сегмент кода, сегмент данных (перемещаемые), абсолютный (по умолчанию)    |
| `NAME имя`                | имя модуля (для объектных файлов)                                         |
| `PUBLIC` / `GLOBAL` имена | экспорт символов для других модулей                                       |
| `EXTRN` / `EXTERN` имена  | импорт символов из других модулей (только при сборке в `.link`)           |

Строки по умолчанию — в кодировке КОИ-7 ЮТ-88 ([26-znakogenerator.md](26-znakogenerator.md)):
20H–5FH как в ASCII, русские буквы — 60H–7EH (строчные русские дают те же коды, Ё = Е,
буквы Ъ нет). С `--charset ascii` русские буквы — ошибка.

## 6. Препроцессор

| Директива                         | Назначение                                                                   |
|-----------------------------------|------------------------------------------------------------------------------|
| `INCLUDE "файл"`                  | вставить исходный файл (поиск — рядом с включающим файлом, затем папки `-I`) |
| `IF выражение` / `ELSE` / `ENDIF` | условная сборка; символы выражения — определённые выше по тексту или `-D`    |
| `IFDEF имя` / `IFNDEF имя`        | условие: символ определён (не определён) выше или ключом `-D`                |
| `имя MACRO [п1,...]` … `ENDM`     | определить макрос; вызов — как команда: `имя а1,а2`                          |
| `LOCAL и1,...`                    | метки, уникальные для каждого раскрытия макроса или `REPT` (`??0001`, …)     |
| `EXITM`                           | досрочно закончить раскрытие макроса (или оставшиеся повторы `REPT`)         |
| `REPT n` … `ENDM`                 | повторить строки n раз                                                       |

Параметры макроса заменяются по словам; внутри кавычек — только запись `&п`; `&` вне
кавычек склеивает слова (`L&N`). Аргумент с запятой пишут в `<…>`. Глубина вложенности
ограничена (макросы и `REPT` — 64, `INCLUDE` — 16).

```asm
SHOW    MACRO   POS,VAL         ; вывести VAL в пару индикаторов POS
        IF      VAL = 0
        XRA     A
        ELSE
        MVI     A,VAL
        ENDIF
        STA     9000H+POS
        ENDM

SQUARES:
I       SET     0
        REPT    5
I       SET     I+1
        DB      I*I             ; 1, 4, 9, 16, 25
        ENDM
```

Пример целиком — `examples/asm/macro.asm`.

## 7. Листинг

`-l ФАЙЛ` пишет листинг в формате `monitor/monitor.lst`:

```
     =9000          DISP    EQU     9000H
                            ORG     0C000H
C000  3E 11         START:  MVI     A,11H
C002  32 00 90              STA     DISP
C005  21 01 90              LXI     H,DISP+1
```

Столбцы 1–4 — адрес (у `EQU`/`SET` — `=значение`); 5-й — пробел у абсолютного адреса,
`'` у смещения в `CSEG`, `"` у смещения в `DSEG`; затем до четырёх байтов кода (длинные
данные продолжаются на следующих строках); 19-й столбец — глубина `INCLUDE`; 20-й — `+`
у строк раскрытия макроса или `REPT` и `-` у строк ложной ветки `IF`; с 21-го — исходная
строка. В конце — таблица символов по алфавиту. При ошибках листинг не создаётся.

## 8. Форматы выходных файлов

| Формат | Расширение      | Содержимое                                                                         |
|--------|-----------------|------------------------------------------------------------------------------------|
| bin    | `.bin`, `.rom`  | байты от наименьшего до наибольшего адреса; пропуски — `--fill`; адрес не хранится |
| hex    | `.hex`          | текстовый дамп, как в журнале и в `programs/*.hex`: `C000 3E 11 32 …`              |
| ihex   | `.ihx`, `.ihex` | Intel HEX: записи данных по 16 байт, запись 03 с адресом пуска из `END`, запись 01 |
| link   | `.link`         | перемещаемый объектный файл для `link-k580vm80a`                                   |

Дамп **hex** — адрес и до 16 байт в строке; строки начинаются на границе 16 байт,
пропуск в памяти начинает новую строку. Эмулятор загружает оба вида `.hex` ключом
`--load ФАЙЛ.hex` (Intel HEX узнаётся по `:` в начале), а `.bin` — ключом
`--load ФАЙЛ.bin@АДРЕС`.

```
C000 3E 11 32 00 90 21 01 90 77 11 02 90 12 C7          (hex)
:0EC000003E113200902101907711029012C77C                  (ihex)
:040000030000C00039                                      (адрес пуска C000H)
:00000001FF
```

Объектный файл **link** — текстовый: подпись `UT88LINK 1`, имя модуля, сегменты с
размерами, данные, символы `PUBLIC`/`EXTERN`, перемещения (`RELOC`), адрес пуска и
завершающая строка `END`. Формат описан в `link-k580vm80a -h`.

## 9. Модули и компоновка

Большую программу можно разбить на модули. Каждый модуль кладёт код в `CSEG`, данные —
в `DSEG` (абсолютные части можно оставить в `ASEG` с `ORG`), экспортирует имена через
`PUBLIC`, импортирует через `EXTRN`. Каждый модуль собирается в файл `.link`, затем
компоновщик раскладывает и связывает их:

```
link-k580vm80a МОДУЛЬ.link... -o ВЫХОД [-t bin|hex|ihex] [-m КАРТА.map]
               [--base АДРЕС] [--cseg АДРЕС] [--dseg АДРЕС] [-e СИМВОЛ] [--fill XX]
```

| Ключ              | Назначение                                                               |
|-------------------|--------------------------------------------------------------------------|
| `-o ФАЙЛ`         | выходной файл, тип — по расширению (`.bin`, `.hex`, `.ihx`) или `-t`     |
| `-m ФАЙЛ`         | карта: сегменты каждого модуля и все символы `PUBLIC` с адресами         |
| `--base АДРЕС`    | адрес `CSEG` первого модуля (по умолчанию C000H); `--cseg` — то же       |
| `--dseg АДРЕС`    | адрес `DSEG` первого модуля (по умолчанию — сразу за кодом всех модулей) |
| `-e СИМВОЛ`       | адрес пуска — символ `PUBLIC` (иначе — единственный `END адрес`)         |
| `--fill XX`       | заполнитель пропусков в bin                                              |
| `-h`, `-he`, `-V` | справка по-русски, по-английски, версия                                  |

Раскладка: `CSEG` всех модулей подряд в порядке командной строки, затем все `DSEG`;
`ASEG` остаются на своих адресах. Перекрытия, неразрешённые и повторные символы, выход
байта за пределы — ошибки с именем модуля, файла `.link` и местом в исходном тексте.
Результат байт-в-байт равен сборке тех же текстов одним файлом через
`asm-k580vm80a --base` с тем же адресом.

Пример `examples/asm/hello-link/` — модуль `main.asm` (главная программа, строки в
`DSEG`) и библиотека `print.asm` (`PRINT` и `NEWLINE`):

```asm
; main.asm                              ; print.asm
        NAME    MAIN                            NAME    PRINT
        EXTRN   PRINT,NEWLINE                   PUBLIC  PRINT,NEWLINE
        PUBLIC  START                           CSEG
        CSEG                            PRINT:  MOV     A,M
START:  CALL    NEWLINE                         ORA     A
        LXI     H,MSG1                          RZ
        CALL    PRINT                           ...
        ...                                     DSEG
        JMP     0F86CH                  CRLF:   DB      0DH,0AH,0
        DSEG
MSG1:   DB      'HELLO FROM TWO MODULES!',0
        END     START
```

```sh
asm-k580vm80a -f examples/asm/hello-link/main.asm  -o main.link
asm-k580vm80a -f examples/asm/hello-link/print.asm -o print.link
link-k580vm80a main.link print.link -o hello-link.hex -m hello-link.map --base 3000
target/release/ut88 --config full --load hello-link.hex --run 3000
```

Карта (`-m`) показывает, что куда легло:

```
  Модуль  Файл        Сегмент  Начало  Конец  Размер
  MAIN    main.link   CSEG     3000H   3014H  0015H
  MAIN    main.link   DSEG     302BH   305AH  0030H
  PRINT   print.link  CSEG     3015H   302AH  0016H
  PRINT   print.link  DSEG     305BH   305DH  0003H
```

## 10. Примеры и команды make

Примеры лежат в `examples/asm/`; в начале каждого файла — комментарий: что делает
программа, как её собрать и запустить.

| Файл                                          | Конфигурация | Что делает                                                                                       |
|-----------------------------------------------|--------------|--------------------------------------------------------------------------------------------------|
| `ones.asm`                                    | minimal      | первая программа журнала ([05](05-programmirovanie.md)): «11» на всех индикаторах, затем `RST 0` |
| `fill.asm`                                    | minimal      | заполнение памяти константой ([07](07-programmy.md)) — байт-в-байт `programs/fill-const.bin`     |
| `gamma.asm`                                   | minimal      | «Гамма» — байт-в-байт `programs/gamma.bin`, текст восстановлен по дампу                          |
| `hello.asm`                                   | full         | две строки через F809H МОНИТОРА-F, возврат в МОНИТОР-F (F86CH)                                   |
| `macro.asm`                                   | minimal      | макросы с `LOCAL`, `REPT`, `IF`/`IFDEF`: сумма квадратов на индикаторах                          |
| `hello-link/main.asm`, `hello-link/print.asm` | full         | два модуля с `PUBLIC`/`EXTRN`, `CSEG`/`DSEG`, компоновка с 3000H                                 |

В «Гамме» сохранён лишний байт журнала `03` (`INX B`) по адресу C069H — с комментарием,
чтобы образ совпал с напечатанным дампом (см. [07-programmy.md](07-programmy.md)).

| Команда                                            | Что делает                                                        |
|----------------------------------------------------|-------------------------------------------------------------------|
| `make asm F=файл.asm [O=файл.hex]`                 | собрать; по умолчанию — `файл.hex` рядом с исходником             |
| `make asm-run F=файл.asm [C=minimal\|full]`        | собрать в `файл.hex` и запустить в эмуляторе                      |
| `make link O=файл.hex M="a.link b.link" [B=адрес]` | скомпоновать модули; карта — рядом с выходным файлом (`файл.map`) |
| `make asm-examples`                                | собрать все примеры (и скомпоновать `hello-link/hello-link.hex`)  |

`make asm-run` (скрипт `scripts/asm-run.sh`) берёт адрес пуска из `END адрес`, без него —
наименьший адрес программы. Конфигурация — из `C=` или угадывается: полная, если в тексте
есть адреса E000H–FFFFH (подпрограммы МОНИТОРА-F, экранное ОЗУ), иначе минимальная.
`UT88=echo make asm-run F=…` только печатает команду запуска эмулятора.

```sh
make asm-run F=examples/asm/ones.asm        # «11 11 11» на индикаторах
make asm-run F=examples/asm/fill.asm        # затем набрать C100 C17F A5 на клавиатуре
make asm-run F=examples/asm/gamma.asm       # затем четыре цифры, например 1002
make asm-run F=examples/asm/hello.asm       # полная конфигурация, текст на экране
make asm F=examples/asm/macro.asm O=macro.bin
make asm-examples
```

Тесты `crates/asm-k580vm80a/tests/examples.rs` проверяют, что `ones.asm`, `fill.asm` и
`gamma.asm` дают байты журнала, и выполняют все примеры в ядре эмулятора.

## 11. Ошибки

Ошибки выводятся как `файл:строка:столбец: ошибка: текст`, все ошибки прохода сразу;
выходной файл не создаётся:

```
prog.asm:2:15: ошибка: неизвестный символ X
prog.asm:3:13: ошибка: неизвестный символ LOOP
asm-k580vm80a: ошибок: 2, выходной файл не создан
```

Ошибку в макросе или во включённом файле сопровождают примечания: где вызван макрос,
откуда включён файл. Ошибки компоновщика называют модуль, его файл `.link` и место
символа в исходном тексте.

## 2. Что даёт и чего стоит переход

winit даёт окно и события, softbuffer — кадр в памяти (`&mut [u32]`, пиксели 0RGB), который
показывается в окне. **Ни виджетов, ни рисования фигур, ни текста там нет** — всё, что сейчас даёт
egui, придётся написать или взять отдельными крейтами:

| Было в egui                                                                                          | Станет                                                                   |
|------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------|
| рендер через OpenGL                                                                                  | программная отрисовка в буфер softbuffer (не нужен OpenGL/драйвер)       |
| фигуры со сглаживанием                                                                               | растеризатор tiny-skia                                                   |
| шрифт и текст                                                                                        | ab_glyph + DejaVu Sans / Sans Mono, вшитые в исполняемый файл            |
| меню, кнопки, флажки, переключатели, ползунок, поле ввода, таблицы, прокрутка, всплывающие подсказки | свой небольшой набор виджетов в немедленном режиме (immediate mode)      |
| плавающие окна внутри главного                                                                       | свои плавающие панели внутри главного окна, как сейчас                   |
| второе окно ОС для отладчика                                                                         | второе окно winit со своей поверхностью softbuffer                       |
| буфер обмена                                                                                         | arboard (копирование и вставка в полях ввода)                            |
| AccessKit и `egui_kittest`                                                                           | свой тестовый «стенд»: кадр рисуется без окна, виджеты ищутся по подписи |

Плюсы: меньше зависимостей и время сборки, нет OpenGL (работает в виртуалках и по X-форвардингу),
полный контроль над циклом кадров и вводом, физические коды клавиш (раскладка ЙЦУКЕН не мешает
клавиатуре ЮТ-88). Минусы: своя библиотека виджетов (~2–2,5 тыс. строк), нет IME и экранного
диктора, все размеры и HiDPI — на нас.

## 3. Архитектура

```
crates/ut88-gui/src/
  lib.rs          Speed, GuiOptions, run(): EventLoop + ApplicationHandler
  platform.rs     окна winit, поверхности softbuffer, перевод событий winit → Input, такт кадров
  gfx/
    mod.rs        Canvas — буфер кадра u32 с размером, отсечением (clip) и масштабом HiDPI
    shapes.rs     прямоугольник (скруглённый), круг, линия с толщиной, выпуклый многоугольник, рамка
    text.rs       шрифт ab_glyph, кэш глифов (символ, размер) → альфа-маска, измерение строки
    image.rs      вывод экрана дисплея 384×… с масштабированием (билинейно, как TextureOptions::LINEAR)
  ui/
    mod.rs        Ui: контекст кадра (Input, Canvas, курсор раскладки, id, фокус, «горячий»/активный виджет)
    layout.rs     горизонтальные/вертикальные ряды, колонки, отступы, сетка (Grid)
    widgets.rs    label, button, checkbox, radio, slider, text_edit, separator, combo, tooltip
    menu.rs       строка меню и выпадающие меню (закрытие по щелчку вне и Esc)
    panel.rs      плавающая панель с заголовком, перетаскиванием, крестиком, прокруткой
    theme.rs      цвета и размеры (тёмная тема, близкая к нынешней)
    registry.rs   список виджетов кадра: подпись, прямоугольник, доступность — для тестов
  app.rs          логика окна (как сейчас) + вызовы ui вместо egui
  draw.rs         рисунок компьютера на Canvas (свои Rect/Pos2/Color вместо egui)
  debugger.rs     отладчик на ui, рисуется во втором окне
  keymap.rs       winit::keyboard::KeyCode вместо egui::Key
  dialogs.rs, loader.rs, settings.rs — без изменений
  app/gui_tests.rs — те же тесты на новом стенде
```

Главные решения:

1. **API виджетов повторяет используемое подмножество egui** (`ui.button("…").clicked()`,
   `ui.checkbox(&mut b, "…").changed()`, `ui.horizontal(|ui| …)`, `menu_button`, `Grid`), чтобы
   `app.rs` и `debugger.rs` переносились почти механически, без переписывания логики.
2. **Ядро кадра не зависит от winit:** `App::frame(&Input, &mut Canvas)` получает уже переведённые
   события (мышь, клавиши с `KeyCode` и текстом, колесо, фокус, размер, масштаб) и рисует кадр.
   winit-обвязка в `platform.rs` только собирает `Input` и показывает буфер. Это делает возможными
   тесты без окна.
3. **Цикл кадров:** `ControlFlow::WaitUntil` на ~60 Гц (или частоту монитора из
   `MonitorHandle::refresh_rate_millihertz`); на каждый кадр — `emulate()` по прошедшему времени
   (как сейчас), рисование, `present()`. Адаптация режима «максимум» (`next_max_budget`) остаётся.
4. **Экономия на рисовании:** рисунок компьютера (корпус, клавиатура, телевизор без экрана)
   рисуется в отдельный кэш-слой и перерисовывается только при изменении размера окна, нажатий
   кнопок или люминофора; на каждый кадр — копия слоя, экран дисплея, индикаторы и интерфейс.
   При необходимости — `present_with_damage` только для изменённых областей.
5. **HiDPI:** все размеры интерфейса в логических точках, умножаются на `scale_factor` окна;
   шрифт растеризуется в физическом размере.
6. **Клавиатура:** для кнопок ЮТ-88 — физические коды `KeyCode` (раскладка не важна), для полей
   ввода — `KeyEvent::text`. Нынешний обходной путь «Ctrl+C/X/V приходят как Copy/Cut/Paste»
   не нужен — winit отдаёт клавиши как есть. Потеря фокуса окном (`Focused(false)`) отпускает
   все нажатые клавиши, как сейчас.
7. **Файловые диалоги — rfd остаётся** (не зависит от egui), с привязкой к окну через
   `raw-window-handle`.
8. **Выход:** `CloseRequested`/F10 → сохранение образа квазидиска (как сейчас в `on_exit`, это
   оговорённое исключение) → `event_loop.exit()`.

## 4. Этапы

Каждый этап заканчивается сборкой, `cargo test`, clippy и fmt без замечаний.

### Этап 1. Графика (`gfx/`)
- `Canvas` над `Vec<u32>`: размер, отсечение, заливка; формат пикселей softbuffer (0RGB).
- Фигуры со сглаживанием: прямоугольник со скруглением, рамка, круг, линия с толщиной, выпуклый
  многоугольник (сегменты индикаторов), градиент корпуса (если используется в `draw.rs`).
- Текст: ab_glyph, вшитый шрифт, кэш глифов, `measure`, выравнивание (аналог `Align2`).
- Картинка: масштабирование экрана дисплея с билинейной фильтрацией.
- Тесты: пиксели фигур и текста (непустая маска, границы, отсечение), быстродействие кадра
  1280×900 в release (замер в `examples/` или тест с `#[ignore]`).

### Этап 2. Рисунок компьютера (`draw.rs`)
- Свои типы `Pos2`, `Vec2`, `Rect`, `Color` (или из `gfx`), перенос `Xf`, `pal`, `case`, `key`,
  `seven_segment`, `cpu_module`, `tv`, `keyboard` с `egui::Painter` на `Canvas`.
- Зоны нажатия `Hits` — без изменений.
- Проверка: рисунки минимальной и полной конфигурации совпадают с нынешними по виду (снимки
  кадров до/после — в `scratchpad`, сравнение глазами пользователя).

### Этап 3. Окно и цикл (`lib.rs`, `platform.rs`)
- `ApplicationHandler`: главное окно «ЮТ-88» (1280×900 полная / 720×680 минимальная,
  минимум 480×400), поверхность softbuffer, перевод событий в `Input`, такт кадров.
- Пока без меню: рисунок компьютера, ввод с клавиатуры и мыши, эмуляция, звук, F-клавиши.
- Первая ручная проверка пользователем: `make full`, `make tetris`, `make base`.

### Этап 4. Набор виджетов (`ui/`)
- Контекст кадра, id виджетов (по подписи и пути), фокус, «горячий»/нажатый виджет, курсор мыши.
- Раскладка: `horizontal`, `vertical`, `columns(2)`, `Grid` (с полосами), отступы, `separator`.
- Виджеты: `label` (в т. ч. цветной), `button` (+ `add_enabled`), `checkbox`, `radio`/`radio_value`,
  `slider` (громкость), `text_edit` (курсор, Backspace/Delete/стрелки/Home/End, вставка из буфера
  обмена, подсказка-плейсхолдер, Enter), `combo` (порт отладчика: чтение/запись), подсказка при наведении.
- Меню: строка меню, выпадающие меню, переход между меню наведением, закрытие по щелчку вне и Esc.
- Панели: плавающие окна с заголовком, перетаскиванием, крестиком, прокруткой колесом и
  полосой; порядок наложения (щелчок поднимает панель).
- `registry`: подписи и прямоугольники виджетов кадра — для тестов.
- Тесты виджетов на стенде без окна.

### Этап 5. Перенос интерфейса (`app.rs`)
- Строка меню: «Машина», «Магнитофон», «Файл», «CP/M», «Программы», «Вид», «Справка» — те же
  пункты и подписи.
- Строка состояния и панель F-клавиш (кнопки F2–F12 щёлкаются мышью).
- Панели: «Магнитофон и файлы» (F8), «Программы из журналов» (F9), «Диск CP/M», «Справка:
  клавиши» (F11), «О программе», «Ошибка».
- Щелчки по кнопкам компьютера мышью только когда над ними нет панели или меню (сейчас это
  проверка `Order::Background`).

### Этап 6. Отладчик во втором окне (`debugger.rs`)
- Второе окно winit «ЮТ-88 — отладчик» (820×760) со своей поверхностью; открывается F12 и из меню,
  закрывается крестиком; события маршрутизируются по `WindowId`.
- Перенос интерфейса: кнопки, «до адреса», регистры с правкой, точки останова (адрес и порт),
  дизассемблер, память с правкой.

### Этап 7. Тесты окна (`app/gui_tests.rs`)
- Стенд `Win` на `App::frame` без окна: `click(label)`, `click_nth`, `menu(top, item)`, `key(KeyCode)`,
  `has`, `has_containing`, `settle` — те же имена, тела тестов меняются минимально.
- Перенести все нынешние тесты (снимки, загрузка программ, магнитофон, программы, меню
  «Машина»/«Вид»/«Справка», громкость и `volume.txt`, `--no-sound`, битые настройки, CP/M,
  панель F-клавиш, F-клавиши с клавиатуры, «максимум», точки останова на «максимуме», перерисовка
  экрана и индикаторов, адаптация бюджета).
- Убрать `egui_kittest` из dev-зависимостей.

### Этап 8. Зависимости, CI, документация
- `Cargo.toml` крейта: убрать `eframe` и `egui_kittest`; добавить `winit 0.30`, `softbuffer`,
  `tiny-skia`, `ab_glyph`, `arboard`; шрифты — в `crates/ut88-gui/assets/fonts/` с файлом
  лицензии, подключаются через `include_bytes!`.
- Проверка «egui выпилен с корнем»: `cargo tree` и `Cargo.lock` не содержат `egui`, `eframe`,
  `epaint`, `emath`, `ecolor`, `egui-winit`, `egui_glow`, `egui_kittest`, `kittest`, `glow`,
  `glutin`, `accesskit*`; в коде, комментариях и документах нет упоминаний egui (кроме истории
  в CHANGELOG и планов).
- CI: пересмотреть системные пакеты (`libgl1-mesa-dev` больше не нужен; проверить нужное для
  X11/Wayland у winit и softbuffer).
- Документы: README (строки 14, 482, 533 — «egui» → «winit + softbuffer», благодарности),

## 5. Риски

| Риск                                                      | Что делаем                                                                   |
|-----------------------------------------------------------|------------------------------------------------------------------------------|
| программная отрисовка 1280×900 (и больше на 4K) медленная | кэш-слой рисунка, перерисовка только изменённого, замер на этапе 1           |
| Wayland: нет заголовка окна без клиентских рамок          | фича winit `wayland-csd-adwaita` (включена по умолчанию)                     |
| в шрифте нет символов `▶`, `⏸` и др. из нынешних подписей | проверить шрифт; недостающее рисовать фигурами или заменить текстом          |
| блокирующие диалоги rfd останавливают цикл кадров         | так же, как сейчас; при паузе эмуляции нет «догоняния» (`debt` сбрасывается) |
| объём своей библиотеки виджетов                           | только используемое подмножество; тесты виджетов на этапе 4                  |
| вид интерфейса изменится                                  | показывать пользователю снимки кадров после этапов 2 и 5                     |
| arboard на Wayland/X11 теряет буфер при выходе программы  | для нас не важно: копируются короткие строки, вставка — главный сценарий     |

## 6. Решения пользователя

По ответам из `03-prompt-winit-softbuffer-to-prompt.txt`:

| Вопрос               | Решение                                                                                                                                       |
|----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| Рисование фигур      | tiny-skia; кадр tiny-skia (RGBA) переводится в 0RGB для softbuffer                                                                            |
| Шрифт                | DejaVu Sans + DejaVu Sans Mono, растеризатор ab_glyph; файлы шрифтов **вшиты в исполняемый файл** (`include_bytes!`), из ОС шрифты не берутся |
| Вспомогательные окна | плавающие панели внутри главного окна, как сейчас; отладчик — отдельное окно ОС, как сейчас                                                   |
| Вид интерфейса       | близко к нынешней тёмной теме                                                                                                                 |
| Буфер обмена         | нужен: arboard, Ctrl+C/Ctrl+V/Ctrl+X в полях ввода                                                                                            |
| Переход              | заменить полностью, без переходного периода; egui и все его зависимости удалить с корнем                                                      |

Следствия:
- шрифт — единственный источник глифов; тест проверяет, что в нём есть все символы всех подписей
  интерфейса (кириллица, `…`, `«»`, `—`, `▶`, `⏸` и др.), недостающие значки рисуются фигурами;
- поскольку переходного периода нет, ветка неработоспособного окна не коммитится: этапы 1, 2, 4
  (новые модули рядом со старым кодом) — отдельными коммитами, а замена `app.rs`/`debugger.rs`/
  `lib.rs` и удаление eframe (этапы 3, 5–8) — одной серией, после которой окно сразу полное.

## 7. Исполнение

Агентами по этапам: 1 и 2 (графика и рисунок) — последовательно, 4 (виджеты) — параллельно с
ними; затем 3, 5, 6, 7, 8. Отклонения — в `NN-deviations-winit-softbuffer.md`. Коммиты — только с
разрешения пользователя, по типам: `feat` (графика, виджеты, окно), `refactor` (перенос кода без
изменения поведения), `test` (стенд и тесты), `build` (Cargo.toml, CI), `doc` (документы).

## 8. Критерии готовности

- в `Cargo.lock` и `cargo tree` нет egui и его зависимостей (список — этап 8); окно работает на
  winit + softbuffer + tiny-skia;
- шрифты вшиты в исполняемый файл, окно запускается в системе без установленных шрифтов;
- все возможности окна на месте: рисунок компьютера, мышь и клавиатура, меню, F-клавиши,
  магнитофон, снимки, программы, CP/M, звук и громкость, отладчик во втором окне;
- все тесты окна перенесены и проходят; `cargo test`, clippy, fmt — чисто;
- пользователь проверил вид и работу вручную.

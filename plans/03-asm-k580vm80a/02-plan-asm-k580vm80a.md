# План: ассемблер КР580ВМ80А `asm-k580vm80a` на Rust

## 1. Принятые решения

| Вопрос           | Решение                                                                               |
|------------------|---------------------------------------------------------------------------------------|
| Выходные форматы | `bin` — образ памяти; `hex` — дамп как в журнале («AAAA XX XX …»); `ihex` — Intel HEX |
| Синтаксис        | мнемоники Intel 8080 как в журнале + макросы, INCLUDE, условная сборка                |
| Листинг          | опцией `-l файл.lst`: адрес, коды, исходная строка, таблица меток                     |
| Размещение       | крейт `crates/asm-k580vm80a` в workspace (библиотека + бинарник), цели make, примеры  |
| Справка          | `-h` — подробная справка на русском, `-he` — на английском                            |
| Объектные файлы  | `-t link` / расширение `.link` — перемещаемый модуль; компоновщик `link-k580vm80a`    |

## 2. Командная строка

```
asm-k580vm80a -f ВХОД.asm -o ВЫХОД [-t bin|hex|ihex|link] [-l ЛИСТИНГ.lst] [-D ИМЯ[=ЗНАЧЕНИЕ]]... [-I ПАПКА]...
asm-k580vm80a -h      # подробная справка на русском
asm-k580vm80a -he     # подробная справка на английском
```

| Ключ          | Назначение                                                                     |
|---------------|--------------------------------------------------------------------------------|
| `-f ФАЙЛ`     | исходный файл (обязателен)                                                     |
| `-o ФАЙЛ`     | выходной файл (обязателен)                                                     |
| `-t ТИП`      | тип выхода `bin`, `hex`, `ihex`, `link`; если задан — расширение `-o` не важно |
| `-l ФАЙЛ`     | листинг                                                                        |
| `-D ИМЯ=ЗНАЧ` | определить символ (для условной сборки)                                        |
| `-I ПАПКА`    | папка поиска для INCLUDE (кроме папки исходного файла)                         |
| `-h`          | подробная справка на русском (см. ниже)                                        |
| `-he`         | та же подробная справка на английском                                          |
| `-V`          | версия                                                                         |

**Подробная справка** (`-h` — по-русски, `-he` — по-английски) — не краткий список ключей, а
справочник: все ключи с примерами, выбор формата по расширению, синтаксис строки, числа и
выражения, все директивы (ORG, EQU, SET, DB, DW, DS, END, INCLUDE, INCBIN, IF/IFDEF, MACRO,
REPT) с примерами, список команд КР580ВМ80А, форматы выходных файлов, пример программы.
Запуск без аргументов печатает краткую подсказку о `-h`/`-he`. `-he` — нестандартный
короткий ключ, поэтому разбор `-h`/`-he` делается до clap (встроенную справку clap отключить).

Тип выхода без `-t` — по расширению `-o`: `.bin`, `.rom` → bin; `.hex` → дамп как в журнале;
`.ihx`, `.ihex` → Intel HEX; `.link` → объектный файл (раздел 5). Иное расширение без `-t` — ошибка с подсказкой.

Сообщения об ошибках — в формате `файл:строка:столбец: ошибка: текст` (с учётом INCLUDE и
макросов); код выхода ≠ 0, выходной файл при ошибке не создаётся.

## 3. Язык ассемблера

1. **Строка:** `[метка[:]] [мнемоника|директива [операнды]] [; комментарий]`. Регистр букв в
   мнемониках, регистрах и директивах не важен; метки — с учётом регистра (решить по
   monitor.asm; записать в отклонения).
2. **Команды:** все 244 команды КР580ВМ80А в мнемонике Intel (таблица — `doc/10-sistema-komand.md`),
   регистры `A B C D E H L M SP PSW`; проверка допустимых операндов.
3. **Числа:** `0C000H`, `0FFh`, `1010B`, `17O`/`17Q`, десятичные, `0x…`, `$…`; символьные
   константы `'A'`; `$` — текущий адрес.
4. **Выражения:** `+ - * / MOD`, `SHL SHR`, `AND OR XOR NOT`, сравнения `EQ NE LT LE GT GE`
   (и `= <> < <= > >=`), унарный минус, скобки, `HIGH`/`LOW`; 16-битная арифметика;
   проверка диапазона байта/слова.
5. **Директивы:** `ORG`, `EQU`, `SET` (переопределяемый символ), `DB`/`DEFB` (байты, строки
   `'…'`/`"…"`), `DW`/`DEFW`, `DS`/`DEFS` (резерв, с необязательным заполнителем), `END`
   [адрес пуска], `INCLUDE "файл"`, `INCBIN "файл"`, `IF`/`ELSE`/`ENDIF` (вложенные),
   `IFDEF`/`IFNDEF`, `MACRO`/`ENDM` с параметрами и локальными метками (`LOCAL`),
   `REPT`/`ENDM`.
6. **Кодировка строк в DB:** КОИ-7 ЮТ-88 — русские буквы переводятся в коды 60H–7FH (как
   знакогенератор дисплейного модуля, `doc/26-znakogenerator.md`); опция `--charset ascii`.
7. **Двухпроходная сборка** с разрешением ссылок вперёд; ошибки: неизвестная метка,
   повторное определение, переполнение адреса, неверный операнд, незакрытый IF/MACRO.
8. **Модули (для объектных файлов):** `PUBLIC`/`GLOBAL` имя[,имя…] — экспорт, `EXTRN`/`EXTERN`
   имя[,имя…] — импорт, сегменты `CSEG` (код), `DSEG` (данные), `ASEG` (абсолютный, по `ORG`),
   `NAME` — имя модуля. При сборке сразу в bin/hex/ihex `EXTRN` — ошибка, сегменты
   размещаются подряд с адреса `ORG`/`--base`.
9. **Значения с признаком перемещаемости (закладывается с самого начала):** каждое значение
   выражения — абсолютное, относительное к сегменту или «внешний символ ± константа»;
   допустимые операции над перемещаемыми: `±` константа, разность двух меток одного сегмента
   (абсолютна), `HIGH`/`LOW`; прочее — ошибка «выражение нельзя переместить». Сборка идёт через
   промежуточное представление «сегменты + перемещения», из которого выводятся и готовые
   форматы, и `.link`.

## 4. Выходные форматы

- **bin:** сплошной образ от минимального до максимального занятого адреса; пропуски (`ORG`
  вперёд, `DS`) заполняются 00H (опция `--fill FF`); перекрытие областей — ошибка.
- **hex (как в журнале):** строки `AAAA XX XX … XX` по 16 байт, выровненные на границу 16,
  как `monitor/monitor.hex` и `programs/*.hex` (формат, который читает эмулятор).
- **ihex:** записи типа 00 по 16 байт, запись 01 в конце; адрес пуска из `END` — запись 03.
- **Листинг:** `АДРЕС  КОДЫ  ИСХОДНАЯ СТРОКА` (длинные DB — с переносом кодов), раскрытие
  макросов, в конце таблица символов (имя, значение, где определён).

## 5. Объектные файлы `.link` и компоновщик `link-k580vm80a`

### Формат `.link`

Свой простой **текстовый** формат (читается глазами, удобно отлаживать), версия в заголовке:

```
UT88LINK 1
MODULE hello
SEGMENT CSEG 0021            ; сегмент и его размер
DATA CSEG 0000 21 00 00 CD 00 00 ...   ; содержимое по смещениям
SEGMENT DSEG 0010
...
PUBLIC START CSEG 0000       ; экспорт: имя, сегмент, смещение
EXTERN PRINT                 ; импорт
RELOC CSEG 0001 WORD CSEG +0005    ; где, вид, на что: сегмент или внешний символ ± константа
RELOC CSEG 0004 WORD EXT PRINT +0000
RELOC CSEG 0010 LOW  DSEG +0002
ENTRY CSEG 0000              ; адрес пуска (из END), если есть
```

Виды перемещений — только три, потому что у КР580ВМ80А нет относительных переходов: `WORD`
(16-битный адрес), `LOW` и `HIGH` (байт адреса). Абсолютный сегмент `ASEG` хранится как есть.

### Компоновщик

```
link-k580vm80a МОДУЛЬ.link... -o ВЫХОД [-t bin|hex|ihex] [--base АДРЕС] [--cseg АДРЕС]
               [--dseg АДРЕС] [-m КАРТА.map] [-e СИМВОЛ]
link-k580vm80a -h     # подробная справка на русском
link-k580vm80a -he    # подробная справка на английском
```

1. Читает модули, раскладывает сегменты: все `CSEG` подряд с `--cseg` (по умолчанию `--base`,
   иначе C000H), затем все `DSEG` с `--dseg` или сразу после кода; `ASEG` — на свои адреса.
2. Сводит символы: каждый `EXTERN` должен найтись среди `PUBLIC` ровно одного модуля.
3. Применяет перемещения, проверяет переполнение байта для `LOW`/`HIGH`.
4. Пишет `.bin`/`.hex`/`.ihx` (тот же модуль вывода, что у ассемблера) и карту `.map`:
   сегменты модулей с адресами, все символы с адресами, адрес пуска.
5. Ошибки: неразрешённая ссылка (какой модуль, где), повторное определение, перекрытие
   областей, переполнение адресного пространства, неверная версия файла.
6. Компоновщик — второй бинарник того же крейта (общий код форматов вывода).

### Отложено (отдельной задачей, если понадобится)

- библиотеки — архивы модулей, из которых подтягиваются только нужные;
- отладочная информация (строки исходника в `.map`).

## 6. Архитектура крейта `crates/asm-k580vm80a`

| Модуль       | Содержание                                                  |
|--------------|-------------------------------------------------------------|
| `lexer`      | разбор строки на метку, мнемонику, операнды, комментарий    |
| `expr`       | выражения и числа                                           |
| `opcodes`    | таблица команд → коды (по образцу `crates/i8080`)           |
| `preprocess` | INCLUDE, MACRO/REPT, IF                                     |
| `assembler`  | два прохода, символы, сегменты памяти, ошибки с позициями   |
| `ir`         | промежуточное представление: сегменты, перемещения, символы |
| `output`     | bin, hex (дамп журнала), ihex, листинг                      |
| `object`     | запись и чтение `.link`                                     |
| `linker`     | раскладка сегментов, символы, перемещения, карта `.map`     |
| `bin/asm`    | CLI ассемблера `asm-k580vm80a`                              |
| `bin/link`   | CLI компоновщика `link-k580vm80a`                           |

Библиотечный API `assemble(source, options) -> Result<Image, Vec<Error>>` — чтобы позже
эмулятор мог собирать `.asm` напрямую (`ut88 --load prog.asm`) — это вне задания, только
заложить возможность.

## 7. Проверка

1. **Перекрёстная проверка с процессором:** для каждого из 256 кодов дизассемблер
   `crates/i8080` → текст → ассемблер → тот же байт (кроме недокументированных).
2. **monitor/monitor.asm** собирается байт-в-байт в `monitor/monitor.bin`, листинг сравним с
   `monitor/monitor.lst`.
3. **Программы журнала:** написать `.asm` для «Гаммы», заполнения памяти константой и
   первой программы «11 на индикаторах» → совпадение с `programs/*.bin`.
4. Юнит-тесты: выражения, директивы, макросы, INCLUDE, IF, ошибки с позициями, выбор
   формата по расширению и `-t`; `-h` и `-he` печатают справку на нужном языке и
   описывают все ключи и директивы (тест сверяет список).
5. Сквозной тест: собрать пример `.asm`, загрузить в эмулятор (ut88-core), выполнить,
   проверить результат.
6. **Компоновка:** программа, разбитая на несколько модулей (`PUBLIC`/`EXTRN`, CSEG/DSEG,
   `HIGH`/`LOW` внешних символов), после компоновки совпадает байт-в-байт с монолитной сборкой
   того же кода; ошибки компоновщика (неразрешённая ссылка, повтор, перекрытие) — тестами;
   `.link` → чтение → запись даёт тот же файл; `-h`/`-he` компоновщика.
7. `cargo test`, clippy, fmt — чисто.

## 8. Интеграция и документация

1. `make asm F=файл.asm [O=файл.hex]` — собрать; `make asm-run F=файл.asm` — собрать и
   запустить в эмуляторе (сложная логика — в `scripts/asm-run.sh`);
   `make link O=файл.hex M="a.link b.link"` — компоновка.
2. Примеры в `examples/asm/`: «11 на индикаторах», заполнение памяти, «Hello» для
   МОНИТОРА-F (вывод строки через F809H), пример макроса, пример из двух модулей
   (главная программа + библиотека вывода) со сборкой через `.link`.
3. Документация: `docs/ASSEMBLER.md` (английский) и `doc/…` или раздел в `manual.md`
   (русский); README — короткий раздел со ссылкой; CHANGELOG.
4. Названия микросхем в текстах — только кириллицей (КР580ВМ80А).

## 9. Порядок исполнения

1. Агент «asm-core»: крейт, лексер, выражения с признаком перемещаемости, команды,
   директивы, промежуточное представление «сегменты + перемещения», два прохода, форматы,
   CLI, тесты 1–2, 4.
2. Агент «asm-macro»: препроцессор (INCLUDE, MACRO, REPT, IF) и листинг — после п. 1.
3. Агент «asm-link»: директивы модулей, формат `.link`, компоновщик, тест 6 — после п. 1.
4. Агент «asm-docs»: примеры, программы журнала на ассемблере (тест 3), сквозной тест 5,
   make-цели, документация.
5. Коммиты — только с разрешения пользователя; по типам `feat`, `test`, `build`, `doc`;
   отклонения — `devi`.

## 10. Критерии готовности

- `asm-k580vm80a -f hello.asm -o hello.hex|.bin|.ihx` выбирает формат по расширению, `-t`
  его переопределяет;
- monitor.asm собирается байт-в-байт; все 244 команды проходят перекрёстную проверку;
- макросы, INCLUDE, IF, листинг работают и покрыты тестами;
- `-h` печатает подробную справку на русском, `-he` — на английском (у ассемблера и
  компоновщика);
- `-o x.link` даёт объектный файл; `link-k580vm80a` собирает модули в bin/hex/ihex с картой,
  результат совпадает с монолитной сборкой; ошибки компоновки понятны;
- make-цели и документация на месте; `cargo test`, clippy, fmt — чисто.

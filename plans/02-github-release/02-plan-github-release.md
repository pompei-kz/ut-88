# План: оформление проекта для публикации на GitHub

Задание: `01-prompt-github-release.txt`.
Дополнения (ответы на вопросы): `03-prompt-github-release-to-prompt.txt`.
Отклонения при исполнении — в `04-deviations-github-release.md`.

## 1. Принятые решения

| Вопрос             | Решение                                                                                       |
|--------------------|-----------------------------------------------------------------------------------------------|
| Язык               | README.md и полное руководство `docs/MANUAL.md` — на английском; русский `manual.md` остаётся |
| Лицензия кода      | MIT OR Apache-2.0 (файлы `LICENSE-MIT`, `LICENSE-APACHE`, поле `license` во всех Cargo.toml)  |
| Материалы журналов | остаются в репозитории; файл `NOTICE.md` с источниками, правами и оговоркой                   |
| Служебные файлы    | CLAUDE.md, plans/, ii_work/, todo.md остаются; `resume` не коммитится (в `.gitignore`)        |

## 2. README.md (английский, быстрый старт)

1. Название, одна-две фразы о ЮТ-88 и эмуляторе, скриншоты окна (минимальная и полная
   конфигурации, «Тетрис»).
2. **Requirements**: Rust/cargo — ссылка https://rustup.rs (и
   https://www.rust-lang.org/tools/install), `make`; системные библиотеки Linux для окна и
   звука (ALSA, X11/Wayland) — команда для Debian/Ubuntu.
3. **Quick start — make commands**: таблица всех команд Makefile, затем по каждой — что
   откроется и что делать дальше.
4. **`make base`** — модуль 1: индикаторы и кнопки, клавиши ПК; простые директивы
   МОНИТОРА: 0/1 (ввод), 2/5 (просмотр), 6/7 (запуск), ШАГ НАЗАД, УСТ; пример — набрать и
   запустить программу «11 на всех индикаторах»; две программы из журнала (например,
   «Гамма» и «Крестики-нолики») — как запустить (`make prog P=…`) и как ими пользоваться.
5. **`make full`** — дисплейный модуль и МОНИТОР-F: приглашение, пара директив (D — дамп,
   M — правка, G — запуск); программы: **«Тетрис»** (запуск, все клавиши, удержание) и
   ещё одна (тест дисплейного модуля или CP/M через `make cpm`) с управлением.
6. Кратко: терминальные варианты (`-t`), горячие клавиши F2–F12 и панель кнопок,
   CP/M и ОС ЮТ-88 (`make cpm`, `make os`).
7. **Ссылка на подробное руководство** `docs/MANUAL.md` (и русское `manual.md`),
   документация по журналам `doc/README.md`.
8. Project layout (крейты, папки), Development (make test / test-all / lint), License,
   Acknowledgements (журнал «ЮТ для умелых рук», В. Бартенев, авторы тестов 8080).

Все примеры в README проверяются запуском (CLI, тесты ядра), клавиши — по коду.

## 3. docs/MANUAL.md

Перевод `manual.md` на английский с тем же содержанием и структурой; ссылки на `doc/`
сохраняются (с пометкой, что документация журналов на русском). В `manual.md` — ссылка на
английскую версию и наоборот.

## 4. Лучшие практики оформления репозитория

1. `LICENSE-MIT`, `LICENSE-APACHE`; `license = "MIT OR Apache-2.0"` и метаданные
   (`description`, `readme`, `keywords`, `categories`, `authors`) в `[workspace.package]`,
   крейты наследуют.
2. `NOTICE.md`: материалы журнала «ЮТ для умелых рук» 1989–1990 (скан, тексты, рисунки,
   дампы ПЗУ и программ) — источник, права редакции, лицензия кода на них не
   распространяется, удаление по требованию правообладателя; тестовые программы 8080
   (источник, авторы, лицензии GPL v2+ / public domain / без лицензии).
3. `CONTRIBUTING.md`: сборка, тесты, стиль (fmt/clippy), формат коммитов (ссылка на
   CLAUDE.md), выравнивание таблиц.
4. `CHANGELOG.md` (Keep a Changelog), версия 0.1.0.
5. GitHub Actions `.github/workflows/ci.yml`: Ubuntu, системные пакеты, `cargo build`,
   `cargo test`, `cargo clippy -- -D warnings`, `cargo fmt --check`; кэш cargo.
6. `.editorconfig`; `.gitignore`: `resume`.
7. Шаблоны issue (`.github/ISSUE_TEMPLATE/bug_report.md`).
8. Бейджи в README (CI, лицензия).

## 5. Порядок исполнения

1. Параллельно агентами: (а) README.md + скриншоты + лучшие практики (п. 2, 4);
   (б) перевод `docs/MANUAL.md` (п. 3).
2. Проверка: ссылки, выравнивание таблиц, `make`-команды, CI-шаги локально.
3. Коммиты по типам (`doc`, `build`, `rules` — новые типы при необходимости согласовать).

## 6. Критерии готовности

- README.md на английском начинается с требований (cargo + ссылка) и команд make; у
  каждой команды — что делать дальше; base и full с директивами и программами, «Тетрис» с
  управлением; ссылка на подробное руководство;
- `docs/MANUAL.md` — полный английский перевод;
- LICENSE-*, NOTICE.md, CONTRIBUTING.md, CHANGELOG.md, CI, .editorconfig на месте;
- `cargo test`, clippy, fmt чистые; CI-шаги проходят локально.

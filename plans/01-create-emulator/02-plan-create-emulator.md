# План: эмулятор компьютера ЮТ-88 на Rust

Задание: `01-prompt-create-emulator.txt`.
Дополнения к заданию: `03-prompt-create-emulator-to-prompt.txt`.
Отклонения при исполнении записываются в `NN-deviations-create-emulator.md` (номер — следующий
свободный в папке на момент начала исполнения).

## 1. Принятые решения (ответы на вопросы)

| Вопрос                | Решение                                                                                      |
|-----------------------|----------------------------------------------------------------------------------------------|
| Конфигурация          | полная: модуль 1 + дисплейный модуль + доп. ОЗУ + квазидиск + МОНИТОР-F + CP/M               |
| Источники             | журналы «ЮТ для умелых рук» 1989–1990 из папки пользователя (см. раздел 2)                   |
| Интерфейс             | оба: графическое окно и терминал (TUI) на общем ядре                                         |
| Внешний вид окна      | похож на настоящий компьютер с фотографий и рисунков журнала                                 |
| Магнитофон            | WAV с настоящим двухфазным сигналом + быстрая загрузка/сохранение бинарных блоков            |
| ПЗУ МОНИТОРА модуля 1 | по умолчанию `monitor/monitor-fixed.bin`, ключом можно указать `monitor.bin` или любой образ |
| Звук                  | да, вывод порта магнитофона на звуковую карту в реальном времени, с выключателем             |
| Проверка процессора   | свои юнит-тесты + известные тестовые программы 8080 (TST8080, 8080PRE, CPUTEST, 8080EXM)     |
| Доп. возможности      | отладчик, загрузка программ из файла, регулировка скорости, снимки состояния                 |
| Программы из журналов | подготовить готовые файлы для загрузки и запуска                                             |
| Документация          | `manual.md` — руководство пользователя эмулятора                                             |

## 3. Архитектура

Cargo workspace в корне репозитория:

```
Cargo.toml                 workspace
crates/
  i8080/                   ядро процессора КР580ВМ80А: регистры, флаги, 244 команды, такты,
                           прерывания, дизассемблер; без зависимостей от остального
  ut88-core/               машина: шина, карта памяти, устройства, тактирование, снимки
    bus                    трейт Bus (память + порты), сборка конфигурации из модулей
    devices/
      cpu_module           модуль 1: ПЗУ 0000–03FF, ОЗУ C000–C3FF, индикаторы 9000–9002,
                           клавиатура (порт A0), магнитофон (порт A1), часы RST 7 раз в секунду
      display_module       дисплейный модуль: видео-ОЗУ, знакогенератор, клавиатура на ВВ55
      ram_module           дополнительное ОЗУ
      quasidisk            квазидиск
    tape                   модель магнитофона: WAV чтение/запись, бинарные блоки
    snapshot               сохранение/загрузка полного состояния
    config                 описание конфигураций (минимальная, полная)
  ut88-audio/              вывод звука через cpal
  ut88-gui/                графическое окно (eframe/egui): вид компьютера + отладчик
  ut88-tui/                терминальный интерфейс (ratatui + crossterm) + отладчик
  ut88/                    исполняемый файл: разбор ключей (clap), выбор GUI/TUI
roms/                      образы ПЗУ (МОНИТОР модуля 1, МОНИТОР-F, знакогенератор, …)
programs/                  программы из журналов: .bin + описание (адрес загрузки, пуска)
tests/roms/                тестовые программы 8080 (скачиваются, с указанием источника)
manual.md                  руководство пользователя
```

Ключевые принципы:

- **Ядро не знает об интерфейсе.** `ut88-core` даёт API: `step()`, `run_for(такты)`, состояние
  индикаторов/экрана, нажатие/отпускание клавиш, магнитофон, снимки. GUI и TUI — тонкие
  обёртки.
- **Точность по тактам.** Процессор считает такты по таблице 8080; машина идёт по
  тактам 2 МГц, часы К176ИЕ5 и магнитофон привязаны к тактам, а не к реальному времени.
  Синхронизация с реальным временем — в интерфейсе (скорость ×1, ×N, максимум, пауза).
- **Конфигурации из модулей.** Минимальная (модуль 1) и полная конфигурации собираются из
  одних и тех же устройств; выбор ключом `--config`.

## 4. Этапы

Каждый этап заканчивается рабочим состоянием: `cargo build`, `cargo test`, `cargo clippy` без
ошибок и коммит по правилам `CLAUDE.md`.

### Этап 1. Разбор журналов 1989–1990 в `doc/`

1. Найти в выпусках из раздела 2 все материалы о ЮТ-88, уточнить страницы.
2. Перевести их в `.md` по образцу модуля 1: текст, таблицы (выровненные), рисунки в
   `doc/img/`, листинги — переписаны по изображениям страниц.
3. Отдельно извлечь дампы ПЗУ (МОНИТОР-F, знакогенератор) и программ в `.hex`, проверить
   контрольными суммами из журналов.
4. Учесть исправления из «Консультационного пункта» (1989-12).

Результат: `doc/` с описанием всех модулей; образы ПЗУ в `roms/`.

### Этап 2. Каркас проекта

Workspace, пустые крейты, `rust-toolchain` не фиксируется (используется установленный
cargo 1.98), edition 2024, `.gitignore` для `target/`, CLI-заглушка `ut88 --help`.

### Этап 3. Процессор КР580ВМ80А (`i8080`)

1. Регистры, флаги (S Z 0 AC 0 P 1 C), все 244 документированные команды; недокументированные
   коды ведут себя как на настоящем 8080 (дубликаты NOP/JMP/CALL/RET).
2. Такты по таблице (`doc/10-sistema-komand.md`), включая условные CALL/RET.
3. Прерывания: INTE, EI с задержкой на одну команду, приём кода команды по INTA (для ЮТ-88 —
   `RST 7`), HLT.
4. Дизассемблер (мнемоника Intel, как в журнале).
5. Тесты:
   - юнит-тесты на каждую группу команд и флаги (DAA, AC, перенос/заём);
   - прогон TST8080, 8080PRE, CPUTEST, 8080EXM с заглушкой BDOS (вывод в строку); 8080EXM —
     сравнение CRC с эталонами настоящего 8080.

### Этап 4. Модуль 1 (минимальная конфигурация)

1. Карта памяти и дешифрация как в схеме: ПЗУ 0000–03FF (с повторением в сегменте
   0000–0FFF), индикаторы в сегменте 9000–9FFF по A0–A1, ОЗУ C000–C3FF.
2. Клавиатура: порт A0, коды как у ПЗУ DD15/DD16 и DD17 (0 → 10H, «ШАГ НАЗАД» → 80H),
   «УСТ» = сброс.
3. Индикаторы: 6 разрядов, знакогенератор К155РЕ3 по таблице 2.
4. Часы: импульс INT раз в секунду (по тактам), программа часов МОНИТОРА.
5. Проверка: МОНИТОР показывает «11», проходят директивы 3 и 4, контрольные суммы
   0181H/18CCH по директиве 8, игры из 1989-02 работают.

### Этап 5. Магнитофон

1. Выход: бит 0 порта A1 с отметкой такта → WAV (44,1 кГц, моно).
2. Вход: WAV → уровень бита 0 порта A1 по тактам; поддержка записей других эмуляторов и
   настоящих кассет (порог, инверсия полярности — МОНИТОР это умеет сам).
3. Быстрый режим: загрузка/сохранение блока памяти в бинарный файл без воспроизведения.
4. Проверка: директива 9 → WAV → директива A восстанавливает данные с той же контрольной
   суммой.

### Этап 6. Звук

Вывод порта магнитофона (и звукового выхода полной конфигурации, если он есть) в звуковую
карту через cpal с буфером, синхронизированным с эмуляцией; выключатель звука. Проверка —
«Гамма» и «Лабиринт».

### Этап 7. Дисплейный модуль, доп. ОЗУ, квазидиск, МОНИТОР-F

По описаниям из этапа 1: видео-ОЗУ и формирование экрана, знакогенератор, клавиатура на
КР580ВВ55А, дополнительное ОЗУ, квазидиск, МОНИТОР-F. Проверка — директивы МОНИТОРА-F,
«Тетрис», «Жизнь», «Болотуду».

### Этап 8. CP/M

Загрузка CP/M с квазидиска по описанию 1990-02/1990-04 (дампы из журнала). Проверка — вывод
оглавления диска, запуск утилит.

### Этап 9. Графический интерфейс (`ut88-gui`)

1. Окно в виде настоящего компьютера по фотографиям и рисункам журнала:
   - минимальная конфигурация — плата модуля 1 с шестью красными семисегментными
     индикаторами и клавиатурой 4×4 + «ШАГ НАЗАД» + «УСТ» (раскладка как на рис. 1 журнала);
   - полная конфигурация — экран дисплейного модуля и полноразмерная клавиатура.
2. Ввод мышью по нарисованным клавишам и с клавиатуры ПК (таблица соответствия в
   `manual.md`).
3. Меню/панель: сброс, пауза, скорость, магнитофон (вставить WAV, запись, быстрая
   загрузка/сохранение), снимки, загрузка программы, звук вкл/выкл.

### Этап 10. Терминальный интерфейс (`ut88-tui`)

Индикаторы крупными цифрами из символов, экран дисплейного модуля текстом, те же функции,
что в GUI, через горячие клавиши.

### Этап 11. Отладчик

В GUI (отдельная панель) и TUI (отдельный экран): регистры и флаги, дизассемблер вокруг PC,
дамп и правка памяти, точки останова по адресу и по обращению к порту, шаг на команду,
шаг с обходом CALL, запуск до адреса, счётчик тактов.

### Этап 12. Загрузка программ и снимки состояния

1. `ut88 --load файл.bin@C000 --run C000`, поддержка `.bin`, Intel HEX, WAV.
2. Снимки: полный образ состояния (процессор, память, устройства, часы, позиция магнитофона)
   в файл; горячие клавиши «сохранить/загрузить».

### Этап 13. Программы из журналов (`programs/`)

Для каждой программы — `.bin` (переписан по изображению страницы и сверен с контрольной
суммой, если она есть) и запись в `programs/README.md`: откуда (выпуск, страница), адреса
загрузки и пуска, как играть. Минимум из 1989-02: заполнение памяти константой, «Реакция»,
«Гамма», «Крестики-нолики», «Лабиринт» (+ поле C200H). Далее — все программы из этапа 1
(«Тетрис», «Жизнь», «Болотуду» и др.).

### Этап 14. `manual.md`

Руководство пользователя: установка и запуск, ключи командной строки, вид окна и
соответствие клавиш, работа с МОНИТОРОМ (кратко + ссылки на `doc/`), магнитофон, снимки,
отладчик, загрузка и запуск каждой программы из `programs/`.

### Этап 15. Завершение

Прогон всех тестов, проверка `manual.md` по шагам, статус плана → «выполнен».

## 5. Зависимости (крейты)

| Крейт                  | Назначение                     |
|------------------------|--------------------------------|
| `eframe` / `egui`      | графическое окно и отладчик    |
| `ratatui`, `crossterm` | терминальный интерфейс         |
| `cpal`                 | вывод звука                    |
| `hound`                | чтение/запись WAV              |
| `clap`                 | разбор ключей командной строки |

## 6. Риски

| Риск                                               | Что делаем                                                       |
|----------------------------------------------------|------------------------------------------------------------------|
| Дампы ПЗУ и программ в журналах плохо распознаются | переписываем по изображениям, сверяем контрольными суммами       |
| В журналах есть опечатки в схемах и дампах         | сверка с «Консультационным пунктом», запись в файл отклонений    |
| Описания какого-то модуля нет в журналах           | фиксируем в отклонениях, согласуем с пользователем               |
| Тестовые ПЗУ 8080 скачиваются из интернета         | сохраняем в `tests/roms/` с указанием источника и лицензии       |
| Звук и реальное время расходятся                   | эмуляция идёт по тактам, звук — с буфером и подстройкой скорости |

## 7. Критерии готовности

- минимальная конфигурация: МОНИТОР модуля 1 работает полностью, все 5 программ из 1989-02
  запускаются из `programs/`;
- полная конфигурация: МОНИТОР-F, экран, игры из журналов, CP/M загружается;
- процессор проходит TST8080, 8080PRE, CPUTEST, 8080EXM;
- запись на «ленту» и чтение обратно дают ту же контрольную сумму;
- GUI похож на компьютер с фотографий, TUI работает в терминале;
- отладчик, загрузка программ, скорость, снимки работают;
- `manual.md` описывает всё перечисленное.

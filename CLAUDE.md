# Правила работы с проектом

## Сообщения коммитов

Формат:

```
TYPE(short-comment) : Краткое описание задачи по-русски

Детальное описание.
```

- Первая строка начинается с префикса `TYPE(short-comment) :`, после него идёт краткое
  описание задачи на русском языке.
- Если в коммите несколько задач, их краткие описания соединяются плюсом `+`.
- После первой строки — два перевода строки (одна пустая строка), затем детальное
  описание.

### TYPE — тип изменения

| TYPE | Когда использовать |
|------|--------------------|
| `doc` | документация |
| `feat` | добавление новой функции |
| `plan` | фиксация написанного плана |
| `rules` | внесение правил работы с проектом |
| `refactor` | реорганизация без изменения содержимого: перенос и переименование файлов, перестройка структуры |

### Новый тип изменений

Если изменение не подходит ни под один тип из таблицы, **коммитить не нужно**. Вместо
этого:

1. описать, что это за изменение и почему оно не подходит под существующие типы;
2. предложить несколько вариантов нового типа (название и когда его использовать);
3. дождаться решения пользователя, внести выбранный тип в эту таблицу и только потом
   коммитить.

### short-comment

Очень краткий комментарий (латиницей, через дефис) по основной задаче коммита.
Например, написание эмулятора — `create-emulator`.

### Несколько типов изменений

Если во время работы сделано несколько задач разного типа, нужно сделать **отдельный
коммит для каждого типа**.

### Примеры

```
doc(magazine-to-md) : Перевод журнала ЮТ-88 в Markdown

Текст статьи разобран из DjVu, вычитан по изображениям страниц
и разложен по файлам doc/*.md; иллюстрации в doc/img/.
```

```
feat(create-emulator) : Эмулятор процессора КР580ВМ80А + загрузка ПЗУ монитора

Реализованы все 244 команды, загрузка monitor.bin по адресу 0000H.
```
